# Archived Requirements: v1.0

All requirements below were satisfied in Milestone v1.0.

## User Stories
- [x] **Auth**: As a user, I want to sign in with email or a magic link so I can access my data securely.
- [x] **Household**: As a user, I want to create and manage multiple family members with their specific nutrition profiles.
- [x] **Planning**: As a user, I want to select specific days and meals (B/L/D) to generate for my household.
- [x] **Generation**: As a user, I want the AI to create a meal plan that respects everyone's dietary needs (multi-recipe if needed).
- [x] **Recipes**: As a user, I want to view clear, step-by-step instructions and ingredients for each planned meal.
- [x] **Shopping**: As a user, I want a consolidated shopping list grouped by category for easy grocery runs.
- [x] **Control**: As a user, I want to see which AI model is currently active and debug my AI prompts.

## Technical Requirements
- [x] **Supabase**: PostgreSQL for data, Auth for identity, RLS for security.
- [x] **Edge Functions**: All AI calls must go through Deno edge functions for security.
- [x] **Ollama**: Local development must support direct `localhost:11434` calls for Ollama.
- [x] **Google Stitch**: All UI components should be generated using the WFM-AI-MEALPLANNER project for a cohesive, minimalist look.
- [x] **State Management**: Meal plans must be versioned by week.
- [x] **Performance**: Recipes and plans should be cached in Supabase to avoid redundant AI calls.

## Visual Requirements
- [x] Minimalist, earthy tones.
- [x] "Cookbook" aesthetic (clear typography, generous spacing).
- [x] Visual meal cards with at-a-glance nutrition.
