# Phase 999.1: Allow cards to be deleted or individually refreshed

## Goal
Enhance the user experience by allowing individual meal slots to be cleared or refreshed with a new AI suggestion without regenerating the entire week.

## Requirements
- [REF-01] Delete/Clear slot: Remove a manual entry or AI-generated recipe from a specific slot.
- [REF-02] Refresh slot: Request a new AI suggestion for a single, unlocked slot.
- [REF-03] Visual Feedback: Provide clear UI actions (icons/buttons) for these operations.

## Technical Approach

### 1. UI Updates (MealSlot.tsx)
- Add "Delete" icon/button (e.g., trash can) to clear the slot.
- Add "Refresh" icon/button (e.g., rotating arrows) to trigger a single-slot regeneration.
- Update `MealSlot.css` for new actions.

### 2. State & Logic (MealPlanner.tsx)
- `handleDelete(date, mealType)`: 
  - Clear `manual_entry` and `recipe` for the specified slot.
  - Update local state and call `plannerService` to persist.
- `handleRefresh(date, mealType)`:
  - Call AI proxy with a targeted prompt: "Give me a single [mealType] suggestion for [date] considering [household profile], avoiding [existing recipes in the week]".
  - Update only the specified slot with the new suggestion.

### 3. Service Updates (plannerService)
- Ensure `plannerService.updateSlot` handles clearing fields (e.g., setting `recipe_id` or `manual_entry` to `null`).

## Verification Plan
- **Manual Verification:**
  - Clear a manual entry and verify it's removed from the grid and DB.
  - Clear an AI-generated recipe and verify it's removed.
  - Refresh an unlocked slot and verify a new recipe appears without changing other slots.
- **Automated Tests:**
  - Add test cases to `meal-plan.test.tsx` for deleting and refreshing slots.
