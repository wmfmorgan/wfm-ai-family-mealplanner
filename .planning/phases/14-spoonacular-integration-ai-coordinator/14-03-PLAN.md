Implement this exact flow:
1. `verifyAuth(req)`
2. Parse `{ household_id, week_start_date, directives }`
3. Create both user and service clients
4. Query today's `spoonacular_usage_log` rows for `household_id` and compute `points_used_today = max(points_used_today) || sum(points_requested)`
5. Compute quota state with `getQuotaState`
6. For each directive:
   - compute `directiveHash = buildDirectiveHash(directive)`
   - call `loadCachedRecipe(serviceClient, directiveHash)` before any provider request
   - if a non-expired cached recipe exists, normalize it into the slot response and continue without calling `fetchComplexSearch` or `writeUsageLog`
   - if the current `quota_status.threshold_reached === true`, call `callAI({ role: 'fallback-generator', edgeFunction: 'recipe-search', householdId })`
   - else call `fetchComplexSearch`
   - read `X-API-Quota-Request`, `X-API-Quota-Used`, and `X-API-Quota-Left` from response headers
   - call `writeUsageLog(...)` with `endpoint: '/recipes/complexSearch'`, `directive_hash: buildDirectiveHash(directive)`, and `daily_limit`
   - immediately recompute `quota_status = getQuotaState({ pointsUsedToday: Number(response.headers.get('X-API-Quota-Used') ?? points_used_today), dailyLimit, threshold })` after each live provider response so the next directive sees the updated threshold state
   - when a grounded provider candidate survives taxonomy filtering, call `upsertRecipeCache({ directiveHash, recipe })` before returning the slot
   - on `402`, no results, or all candidates rejected by taxonomy, fall back to `fallback-generator`
7. Normalize provider results into this persistence-ready recipe shape:
