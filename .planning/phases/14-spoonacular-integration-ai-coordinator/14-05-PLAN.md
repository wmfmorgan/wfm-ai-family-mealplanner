<objective>
Close three UAT gaps identified after phase 14 human testing.

Gap A (major): `DEFAULT_SPOONACULAR_DAILY_LIMIT` in `_shared/spoonacular.ts` is a module-level const that evaluates `Deno.env.get('SPOONACULAR_DAILY_LIMIT')` at import time — before the Supabase edge runtime injects secrets. It always resolves to `'50'`. With threshold 0.8, `thresholdPoints = ceil(50 * 0.8) = 40`. Any session with 40+ points of accumulated usage hits the `threshold_reached` guard at `recipe-search/index.ts:462` and short-circuits every directive to `buildFallbackSlot()`, never reaching `fetchComplexSearch`. Fix: replace the module-level const with a function that reads the env var at call time.

Gap B (major): `DEFAULT_QUOTA_STATUS` in `src/lib/services/spoonacular.ts` hardcodes `daily_limit: 50` and `points_left_today: 50`. This constant is used as the fallback when no DB row exists and as the floor inside `normalizeQuotaStatus`. Because Gap A causes `daily_limit: 50` to be written into DB rows during live calls, fixing Gap A is necessary but not sufficient — the frontend constant must also change to 150.

Gap C (minor): CSS classes `.generation-matrix`, `.matrix-row`, `.matrix-cell` are applied in `Settings.tsx:155-177` but are absent from `Settings.css`. Browser renders them as unstyled block divs in a vertical list. JSX structure is correct.

Purpose: Restore the core value proposition of the phase — real Spoonacular-grounded recipes instead of AI fallbacks, correct quota display, and a usable generation preferences matrix.
Output: Three modified files, no new files, no schema changes.
</objective>
